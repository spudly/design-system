List and card widgets gain skeleton loading states (#278, tranche 1 of 5). CardRow, ListRow, DiscoveryCard, PreviewCard, CommentItem, StatCard, StatBand, LogEntryCard, TokenRow, MasonryGrid, and CheckboxSelectList each accept a `loading` prop: while loading, text runs swap for text skeletons at the same line count, thumbnails swap for box skeletons at identical geometry, and no real content, links, or actions render; the loading region is marked busy for assistive tech. The collection widgets render exactly 3 dummy items while loading — CheckboxSelectList's centered spinner is replaced by 3 skeleton checkbox rows, MasonryGrid lays out 3 box-skeleton items without calling `renderItem`, and StatBand shows 3 dummy stats. The Card and SectionCard shells accept `loading` too: SectionCard skeletonizes its title, and both shells propagate the state to nested widgets through the internal LoadingScope, so hosts set one prop on the composite instead of threading it into every row. Test: render each named widget with `loading` (or open its Loading story) and confirm skeletons appear with no real text or actions; render without `loading` and confirm the widget is unchanged.
