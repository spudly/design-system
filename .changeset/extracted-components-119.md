New shared components (#119 extraction set), shipped standalone so every app composes the same units — these are the components the #119 tranche PRs inventoried as extraction-required during their adoption rounds: `PanelStack` (a section panel's content column: 16px inset and 16px block separation, owned outright), `Toolbar` (a fixed-shell page's pinned bar: hairline bottom divider, 16px/12px inset, items wrapping when the bar narrows), `CandidateList` (a heading over one tinted card per candidate awaiting activation, each card's Activate action rendering only when the host passes its callback and disabling while an activation is pending), `LogEntryCard` (a log entry: dated header with an optional star rating, an optional notes body, and an optional Delete action that renders only with its callback and carries the caller-composed entry-specific accessible name), `NutritionPanel` (a per-serving nutrition section in three states — a loading line, an unavailable state with an Estimate action, and the ready state with a "Per Serving" header, an optional Refresh action, one hairline row per nutrient, and the caller's disclaimer), `RecipeOverviewPanel` (a recipe's overview header — hero image, title, status badge fed a caller-resolved tone and label, description, the servings/prep/cook stat band, and the tag row — shared by RecipeDetailPage and PublicRecipePage), `RecipeIngredientsPanel` (a recipe's ingredients section — the servings stepper, the scale preset-or-custom selector, the pressable ingredient rows with missing ones dimmed, and the substitutions block — shared by both recipe surfaces), `RecipeInstructionsPanel` (a recipe's step cards in step-number order with the active step highlighted, shared by both recipe surfaces), `PreviewCard` (a framed preview panel: fixed gray3 border on the surface fill, an optional title, host-rendered preview content, and an optional actions row), `BadgeCardRow` (a compact card row presenting a colored badge with trailing text actions passed as data), `TrailingActionsRow` (a leading group and its actions spread to opposite ends, wrapping instead of overflowing at narrow widths), `ButtonStack` (a stack of full-width buttons at the 12px rhythm), `CheckRow` (a check-off row whose whole body is the checkbox — drawn box, bold label with muted inline detail over a hairline, checkbox semantics with web keyboard activation, checked rows struck through), `StepOverlay` (a full-screen step-reader shell: dark absolute-fill scrim, a translucent Done pill with button semantics and web keyboard activation, eyebrow lines over the step body, and caller-composed step navigation below), `FieldColumns` (a row of equal-width form-field columns with a 12px gutter; children that render nothing get no column), and `FormSubmit` (a form's submit row with its own 16px of separation above the action). Also: `Card` gains a `compact` variant (filled, no border — 12px padding, medium radius, small shadow) for dense rows and inline editors, the treatment folded in from the former CompactCard. On a @spudly/ui bump, re-check in Storybook: Components/PanelStack (Default), Components/Toolbar (Default), Components/CandidateList (Default, ReadOnly), Components/LogEntryCard (Default, WithoutAction), Components/NutritionPanel (Ready, Loading, Unavailable), Components/RecipeOverviewPanel (Default, Minimal), Components/RecipeIngredientsPanel (Default, Plain), Components/RecipeInstructionsPanel (Default), Components/PreviewCard (Default, NoTitle, NoActions), Components/BadgeCardRow (Default, DeleteOnly), Components/TrailingActionsRow (FieldAndAction, ContentAndTextActions, Narrow), Components/Card (Compact), Components/ButtonStack (Default), Components/CheckRow (Default, Checked, LabelOnly), Components/StepOverlay (Default), Components/FieldColumns (Default), and Components/FormSubmit (Default), against docs/manual-tests.md.
