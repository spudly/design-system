BREAKING — pages only (#298): `@spudly/ui` now exports page components only, from the package root. Every page — RecipesPage, DiscoverPage, MealPlansPage, MealPlanDetailPage, RecipeDetailPage, PublicRecipePage, PublicPageFrame, MealDetailPage, MealsHubPage, MealCookingModePage, MealFormPage, MealPlanFormPage, ShoppingListPage, TagsPage, HomePage, LandingPage, SignInPage, SignUpPage, ForgotPasswordPage, ResetPasswordPage, ProfilePage, FeedbackPage, AddRecipeMenuPage, AiSessionPage, ImportTextPage, ImportUrlPage, ImportImagePage, ImportReviewPage, RecipeFormPage, EditRecipePage, ManualEntryPage, EditVersionPage, MemorizeReviewPage, VerseSearchPage, MyVersesPage, MemorizationSessionPage, MemorizeSettingsPage, LegalDocumentPage — and its view-model types are imported as `import { RecipesPage } from "@spudly/ui"`. The `@spudly/ui/pages` and `@spudly/ui/icons` subpath exports are removed; there are no subpath exports at all.

No longer exported from anywhere in the package: widget components (Button, Dialog, Card, TextField, SelectField, and every other component), composite/form components (SignInForm, SignUpForm, ForgotPasswordForm, ResetPasswordForm, NutritionGoalsForm, AccessTokensPanel, LegalSection, and the rest), icon components (Icon, PrintIcon, ShareIcon, and the rest), design tokens (`tokens`), themes (`baseTheme`, `eciperayTheme`, `memorizeTheme`) and the tag-color API (`tagColorNames`, `tagColorNameForHex`, and friends), and the Tamagui config factories (`createTamaguiConfig`, `createStorybookTamaguiConfig`, `createOnDeviceStorybookTamaguiConfig`, `resolveFontFamily`). Those modules still exist inside the design-system repo as the internal building blocks the pages are composed from; they are not part of the published package surface.

What apps must change before taking this version: import every page (and page type) from the `@spudly/ui` root instead of `@spudly/ui/pages`; stop importing widgets, icons, tokens, themes, tag colors, and config factories from `@spudly/ui` or `@spudly/ui/icons` — compose screens from page components instead, and supply any theming/config the app still needs from app-owned code. Rendering is unchanged: no page or component changed its markup, layout, or behavior in this release — only the package's export surface changed. On a bump, re-check in Storybook that each app's screens still render through their pages (for example Pages/Eciperay/RecipesPage and Pages/Memorize/VerseSearchPage stories) and that no app code still imports a removed name.
