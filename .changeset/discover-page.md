New DiscoverPage for @spudly/ui/pages (Eciperay's public recipe catalog, the web `/discover` surface) plus a standalone DiscoveryCard widget. DiscoverPage renders the page title, a collapsed filter bar (search plus a Filters button that opens an add-filter chooser — ingredient, calorie range, satiety range, and sort controls appear only once added, each with a Remove control that clears it — the same pattern as RecipesPage), and the catalog list. Each row is a DiscoveryCard: thumbnail, title, and one subtitle line the app composes ("By {author} · {rating} · {satiety}"). Cards are real links — the app passes each recipe's permalink as the card's `href` and on web the card renders as an anchor to it, so public recipes stay crawlable and open-in-new-tab works; there is no press callback. The page's states: a spinner while the first page loads (filter bar stays mounted), an EmptyState message when nothing matches, a footer spinner while the next page loads (pagination fires from the list's end-reached signal), and — new versus the retired web view, which spun forever on a failed fetch — an error alert showing the app's `errorMessage` when the first load fails. On a @spudly/ui bump, re-check in Storybook: Pages/Eciperay/DiscoverPage's Default story lists the cards as links to their `/recipe/{id}/{slug}` permalinks, FilterChooserOpen and WithFiltersAdded show the chooser and the added Ingredient/Sort controls, Loading keeps the filter bar over a spinner, Empty shows the no-matches message, ErrorState shows the error alert, and LoadingMore shows the footer spinner; Components/DiscoveryCard's Default story renders the card with its subtitle and WithoutSubtitle renders the title alone.
