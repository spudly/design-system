Add MemorizationSessionPage (spudly/design-system#49), Memorize's memorization session — the word-blanking drill screen — as a controlled page component behind the `@spudly/ui/pages` subpath, following the Wave A page ports. The session engine stays app-side in @memorize/core (tokenizing, blank selection, grading, peek counting, round advancement, persistence); the app drives the view through a state union — `{ state: "not-found", onBack }` renders the app screen's missing-verse branch ("Verse not found." and its primary Back button), and `{ state: "ready", ... }` renders the drill: ghost Back button, the reference heading, the round hint and StepDots from the numeric round view-model (`roundIndex` / `roundCount`), the passage as VerseText in a Card, and the advance button whose label switches on `isFinalRound`. The words cross as view-models — `{ text, blank?: { revealed } }` — and a blank press reports the word's index via `onBlankReveal(wordIndex)`; the retry feedback crosses as a pre-composed `feedback` string (its peek/blank counts are engine numbers) and renders as the warning alert. The union deliberately has no "loading" member (the app gates on its store above the screen) and no "complete" member (finishing the final round navigates away), and the contract carries no render slot — the drill's one interactive primitive, BlankWord, is already a DS component, so every element is a DS primitive over view-model data. This is the real screen, not the #44 demo, which invented a ProgressBar and an "End session" button the drill does not have.
