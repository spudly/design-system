Button gains an icon slot: pass a design-system icon component (PrintIcon, ShareIcon, … from `@spudly/ui/icons`) as Button's `icon` prop and Button renders it to the left of the label — sized for the button's size (18/20/24px glyphs for sm/md/lg) and inked in the same color the variant gives its label in the active theme. There are no icon styling props; Button owns the slot's styling completely. With no label text, Button renders icon-only: the glyph centered in a square touch target (44px sm, 48px md, 56px lg — never under the 44px floor), and `accessibilityLabel` is then required, since there is no visible text to name the button. Variants (primary, secondary, ghost, danger), the disabled dim and announced disabled state, and press behavior are exactly as for labeled buttons. On a @spudly/ui bump, re-check Components/Button in Storybook: WithIcon shows the printer glyph left of the "Print recipe" label in the variant ink with an even gap; IconOnly shows only the glyph, centered in its square; IconSizes grows the glyph and the square sm → lg in both rows; IconDisabled (labeled and icon-only) does not respond to presses; IconPressCounter increments when the button is pressed (and via Enter/Space on web); and the icon-only button is findable by its accessible name ("Print recipe") with no `accessibilitylabel` attribute in the DOM.
