Tabbed-shell frame page (#438 Part 5): a new exported page, `TabbedShellPage`, renders a tabbed app's shell — the app title, the tab bar, and the active surface — for hosts whose shell had no design-system component (Memorize's web and native shells hand-rolled theirs; DS #437). Tabs cross as data: each tab has an id and a label, and in the default button form an optional icon NAME from the design system's semantic icon set plus the tab's content; tabs that navigate instead take the link form, where each tab carries a real href. The active tab's content renders through an internal lazy slot: while a tab's lazily loaded content is pending, the shell shows the design system's loading spinner; if the chunk fails to load, the shell shows the established "This section failed to load." alert with the "Reload the app" recovery, and the tab bar and other tabs stay usable. Switching tabs clears a failure. While a non-tab surface (Memorize's drill view) is open, the shell shows it in place of the tab content with no tab selected. Like every page, the shell accepts the standard optional footer data; Memorize supplies none, so no footer band renders for it. Test by rendering a tabbed shell with several tabs, switching tabs, and forcing a tab's content to suspend and to fail.
