The #119 dedupe: the components the page tranches coined independently are shipped once, canonically — and the chip components are removed. **Breaking:** `ActionChip` and `ToggleChipGroup` are deleted (Stephen's ruling: chips are removed entirely; buttons everywhere). Their built-in consumers are migrated in this release: the recipe pages' servings/scale block now uses the new `PresetValueSelector`, RecipeFormPage's status picker is a row of toggle Buttons, and its tag picker is a row of selectable Badges (Badge gains a selectable form: pass a press handler with `selected` and the badge is a toggle — the selected badge renders in the primary fill with the on-primary label ink, announced as pressed; a Badge with no press handler stays display-only). Any other host using the chips must move to Button — a labeled action is a `Button` in any variant (the href form covers navigation), and a selectable pill is Button's new toggle form: pass `selected` to a press-form Button and the selected member renders in the primary fill with the on-primary label ink, announced as pressed (`aria-pressed` on web, the selected accessibility state on native); the href form takes no `selected`. Display tags are unchanged — `Badge` was never a chip; it gains the selectable form above for tag pickers.

New canonical components (each app-agnostic, content caller-supplied): `RatingsCard` (the two-rating card — community average plus the viewer's own stars — appearing once where the public and signed-in recipe pages each coined it), `StatusBadge` (a status pill whose `tone` and `label` are both caller-passed — there is deliberately no design-system status vocabulary), `SectionHeading` (the bare subheading treatment, no built-in padding — the parent owns the inset), `CatalogFiltersBar` (the catalog search + filter bar: the filter and sorter definitions now cross as data in a `filters` prop — nothing about any app's filter set is hardcoded — with added filters removable and a result count), `CatalogHeader` (catalog title over its controls), `PresetValueSelector` (a labeled preset-or-custom value selector: equal-width preset toggle Buttons in one non-wrapping row plus a Custom slot that turns into a decimal number input when pressed, commits a positive entry through the same `onChange`, and afterwards shows the applied value selected — the replacement for the per-page scale chips), `StepList` (numbered steps with optional heading rows), `MarkableRow` (a card row with a trailing mark toggle), `SuggestionPanel` (titled suggestion entries), `TagList` (a recipe's display tags as Badges in a wrapping row), `FieldStack` (titled groups over a vertical stack), `TextActionCardRow` (a card row whose trailing control is a text action), `ScreenShell` / `ScrollShell` / `SessionShell` / `PinnedHeaderShell` (the page shells, composed on ScreenShell + `ScrollRegion` — one shell implementation), `FormStack` and `FormHeading` (form rhythm and title; FormHeading gains an optional `subtitle` line), `LabeledField` / `LabeledGroup` / `FieldLabel` (label rows over one shared implementation — 4px separation over fields, 8px over other controls; on web FieldLabel renders a real label element whose `for` names the field control, via the wrappers' `fieldId`), `RevertAction` and `ChangedListBanner` (the version-diff affordances, composed on TextAction), `ListLoadingState` (the catalog list loading state — centered, carrying no spacing of its own; it renders directly in a list's loading-more slot too, and a list's error renders the `Alert` component directly — no middleman state components), `CenteredText` (a centered text line, also the home of the retired StatusMessage), `SearchRow` (a search field plus trailing actions), `RemovableField` (a removable value row), `BrandLink` (the wordmark as a real link with an `href` — no press callback), and the public chrome: `PublicFrameLayout` / `PublicFrameHeader` / `PublicFrameFooter` plus `DocumentHeader` / `DocumentFooter`, all unified on the href contract — **breaking:** the frame header takes `signInHref` instead of a press callback and the frame footer takes its links as caller-supplied `links` data (`{label, href}` entries rendered in order — no privacy/terms routes are named by the component), because everything that navigates is a link and content is the caller's.

Shared reconciliations, one implementation each: `Button` gains the semantic `grow` flag on both its press and href forms; `TextField` and `SelectField` gain the same `grow`; `TextAreaField` gains size steps (`md`/`lg`/`xl` heights); `Text` gains `muted` and `success` variants; `TextLink` gains a `tone="muted"` form. On a @spudly/ui bump, re-check in Storybook: Components/Button (Toggle: pressing a pill selects it and moves the primary fill; ToggleStates: selected renders primary-filled, unselected secondary, selected-disabled dimmed), Components/PresetValueSelector (Default: ½×/1×/2×/3× presets with 1× selected; CustomSelected: the Custom button shows 2.5× selected; pressing Custom swaps in the number input), Components/CatalogFiltersBar (Default: a search row, Filters button, and the caller's sorter; WithFilters: added filters listed with remove buttons), Components/RatingsCard, Components/StatusBadge (Tones: one badge per tone, labels caller-chosen), Components/Badge (Selectable: pressing a pill toggles its primary fill; Selected: renders pressed), Components/SectionHeading, Components/ListLoadingState (Default: the spinner centered with its label, no offset of its own), Components/FieldLabel (Associated: on web the label renders as a real label element and clicking it focuses the field), Components/PublicFrameFooter (Default: the caller's links render in the order passed), and the migrated pages — Pages/Eciperay/RecipeDetailPage and PublicRecipePage (the Scale row is a button row, the selected scale primary-filled) and RecipeFormPage (Status is a toggle-button row; Tags are selectable Badges, the selected tag primary-filled) — against docs/manual-tests.md.
