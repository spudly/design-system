Page and frame coverage for the widget uses the #438 Part 0 audit found in host apps (Part 3): hosts no longer need to compose these surfaces from individual widgets. New pages: CookingModePage (single-recipe cooking mode — step overlay with progress dots, prev/next navigation, and the scaled-ingredients panel between the step label and the step body), PayPage (checkout-completion card with unconfigured / needs-transaction / opening / closed / error states), ConsentPreferencesPage (the standalone privacy-choices page showing the current analytics-consent choice with Accept / Decline / Withdraw actions), AuthConfirmationPage (post-auth confirmation screen with an optional back link), and RouteErrorPage (not-found and unexpected-error router fallbacks with a home link). RecipeDetailPage gains data props for its sharing section, comments section, and three confirmation dialogs (recipe delete, cook-log delete, nutrition notice), rendered from new internal views (RecipeSharingView, RecipeCommentsView, ConfirmActionView) when supplied; the existing render slots remain as a fallback. ProfilePage gains typed data props for four profile sections (SubscriptionView, AccountDataView, TransferRecipesView with its RecipeExportPickerView, FeedbackPreferenceView), rendered at their existing slot positions. ImportImagePage gains an optional "Import anyway" duplicate-override action. RecipesPage gains own-section load-more states (a loading row and an error row with a retry action after the own recipes). StepOverlay gains an optional accessory slot rendered between the step label and the body. The new section views are internal building blocks and are not exported from the package root.
