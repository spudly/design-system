RecipesPage is now the unified Recipes browse page: one page renders the user's own recipes first — the recipes they created plus the recipes shared with them, with preferred placement at the top — followed by public discovery recipes, all on a single scrolling page. There is ONE search field and ONE filter set covering the whole unified collection, so searching or filtering narrows both sections together. Recipes that were shared with the user appear inside the "your recipes" section (not on a separate screen), marked with a caller-supplied badge such as "Shared with you" so they are distinguishable from the user's own creations; public recipes below render as cards linking to each recipe's permalink. Each section loads, fails, and empties independently: a public-discovery load that fails or comes back empty shows that section's own error or empty message without hiding the user's recipes, and vice versa — when the user has no recipes of their own yet, their section shows its empty message instead of disappearing. This is a breaking change for hosts: RecipesPage's props are now sectioned (`ownTitle` / `ownRecipes` / `loadingOwn` / `ownErrorMessage` / `ownEmptyTitle` / `ownEmptyBody` and the matching discovery-section props `discoveryTitle` / `discoveryRecipes` / `loadingDiscovery` / `discoveryErrorMessage` / `discoveryEmptyTitle` / `discoveryEmptyBody`, with shared items marked through the item's new `badgeLabel`), replacing the old single-list `recipes` / `loading` / `emptyTitle` / `emptyBody` props. DiscoverPage is unchanged and remains available; its removal is a follow-up once hosts adopt the unified page.
