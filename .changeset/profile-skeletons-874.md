ProfilePage renders a skeleton loading state (#874, following the #278 pattern), so hosts can mount it before the profile data resolves instead of gating on a spinner. ProfilePage gains an optional `loading` prop: while loading, the email line renders as a bone and the flag is forwarded to every composed section view (Subscription, NutritionGoals, AccessTokens, ShowLess, AuthorDisplay, FamilySharing, FeedbackPreference, TransferRecipes, AccountData), each of which renders its own skeleton; a section's own `loading` prop still applies when the page flag is off. AuthorDisplayView gains the `loading` prop it was missing: its section card renders in its loading scope so the display-name field, show-my-name checkbox, and Save button skeletonize, and no stored settings or error render. ProfilePage gains a `Loading` story pinning the state. Verify after adopting: passing `loading` to ProfilePage shows every section as a skeleton with no real profile data, and omitting it renders the page exactly as before. This is a partial tranche of #874 — the remaining pages and views without skeleton states are inventoried in the pull request's audit table and follow in a later tranche.
