Fix web accessibility names for Button and the components built on it: on web, a Button given an `accessibilityLabel` now renders it as `aria-label` (and `accessibilityState` as `aria-disabled` / `aria-selected` / `aria-checked` / `aria-busy` / `aria-expanded`), instead of leaking the React Native props as raw `accessibilitylabel` / `accessibilitystate="[object Object]"` HTML attributes with no accessible name. This gives every labeled Button a real accessible name on web — most visibly BlankWord in Memorize drills, whose hidden blanks are now announced (and findable by role+name in tests) as "Reveal blank word N of M", and whose revealed words are announced as "Revealed: <word>". The same translation now covers Text-based actions (TextAction, TextLink, BackLink), ToggleChipGroup chips, RatingForm's Skip/Save actions, ColorPickerField swatches, SearchField's "Clear search" button, StarRatingInput's stars, StepDots, and Avatar. Native (React Native) rendering is unchanged. On a @spudly/ui bump, re-check: BlankWord hidden blanks and labeled Buttons in Storybook (Components/Button, Components/BlankWord) expose their labels as accessible names on web, with no `accessibilitylabel` attribute in the DOM.
