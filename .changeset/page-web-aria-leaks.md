Fix the remaining web accessibility leaks from #235: page-level pressable rows and Tamagui Checkbox/Progress primitives no longer render React Native accessibility props as raw HTML attributes on web. ShoppingListPage's check-off rows now expose their line name, checkbox role, and checked state (findable as a named checkbox); MealDetailPage and MealPlanDetailPage recipe rows, MealPlansPage and MealsHubPage rows, AiSessionPage's "Cancel session" action, MealCookingModePage's "Done" action, and RecipeFormPage's revert actions now expose a real button role on web; RecipeDetailPage's Custom scale chip is a named button and its viewer-rating wrapper reports its disabled state as `aria-disabled`; ChecklistRow's checkbox and ProgressBar now carry their labels as `aria-label` (ProgressBar no longer renders `accessibilityvalue="[object Object]"`); and TextField, TextAreaField, CheckboxField, TextLink, BackLink, OptionCard, and Alert translate caller/internal accessibility props the same way, so labeled fields and link/button/alert semantics reach the web accessibility tree. Native (React Native) rendering is unchanged. On a @spudly/ui bump, re-check in Storybook: ShoppingListPage rows (Pages/ShoppingListPage), ChecklistRow (Components/ChecklistRow), and ProgressBar with a label (Components/ProgressBar) expose their names/roles in the web accessibility tree, with no `accessibilitylabel` / `accessibilitystate` / `accessibilityrole` attributes in the DOM.
