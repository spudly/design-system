New page: AppShellPage — the routed app shell for page-only hosts. A host renders it once around its current page and passes the brand (label + home href), the nav as data (each item an id, label, href, and optional icon name), the active item's id, optional header actions (each an href link or a press callback), and optional BigFooter data; the shell renders the shared top-bar (brand wordmark link, nav links with the active item in the primary-filled treatment, header actions), slots the page through the internal lazy boundary (loading state and failed-chunk fallback included, no host-side boundary import), and renders the one BigFooter when footer data is supplied. TabbedShellPage's header now renders through the same top-bar composition, so the tabbed and routed shells are one chrome. Testable terms: open the AppShellPage stories (Pages/Eciperay/AppShellPage) — Default shows the Eciperay wordmark linking home, the seven nav items with icon glyphs and Recipes filled as current, a Sign out action at the right, and the footer band; NoIcons shows the same nav label-only; LinkActions shows Sign in / Create account as real links; NoFooter shows no footer band; ChunkFailedContent shows the failed-chunk fallback inside the shell with the top bar intact. Hosts can now retire hand-built shell chrome (Eciperay's host AppShell and its temporary host-sourced nav icons) in favor of this page.
