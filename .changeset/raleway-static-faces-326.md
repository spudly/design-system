Native font registration changes from one variable font to static per-weight faces. Apps on iOS and Android must now register four static fonts — static instances of Raleway, renamed `UiSans` because Raleway's OFL license reserves the "Raleway" name against modified versions, and these instances are modified versions — under the exact names `UiSans` (400), `UiSans-Medium` (500), `UiSans-SemiBold` (600), and `UiSans-Bold` (700) — the names the typography tokens declare as `sansNativeFaces` / `sansNativeAndroidFaces` — instead of registering the single Raleway variable font under `Raleway`. The four font files live in the design-system repository under `apps/storybook/assets/fonts/` (the published package ships only `dist/`) — copy them from there, and bundle the accompanying `OFL-Raleway.txt` license file with them. The tokens also declare `normal`/`bold` fontWeight keyword aliases for the 400/700 faces, so keyword weights select the same static faces. Web registration is unchanged (web loads the unmodified Raleway under its own name). Why: with the variable font registered, Android resolved the medium (500) weight numerically against it, and that resolution was nondeterministic across app launches — the same medium-weight text rendered in two different weights from launch to launch (first seen as the PublicPageFrame Android visual-regression captures flipping between two pixel-stable states, #326). A static face renders only its own weight, so weight selection is now deterministic. On a @spudly/ui bump, re-check on Android: the public frame's Sign in link and Privacy Policy / Terms of Service footer links (medium weight) render at the same weight on every app launch, and the frame's footer band keeps the same height across launches; body text (400), the wordmark (600), and headings (700) are unchanged.
